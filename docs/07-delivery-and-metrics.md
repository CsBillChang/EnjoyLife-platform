## 量化口径

- 热点店铺 P95：明确接口、固定店铺数据、热点分布、缓存冷/热状态、请求数或速率、并发、预热和测量时长。以仅 MySQL 的实现为基线，对照 Redis 与两级缓存；使用同一负载，记录吞吐、回源次数、错误、超时和资源占用。
- 分位数：P95 表示按预定样本范围排序后第 95 百分位耗时；写明是成功响应、全部已完成请求还是某类终态。失败/超时/未完成数量单独完整报告，不能排除慢失败后宣传整体延迟。
- 异步成单 P95：目标口径原本是从购买请求持久化受理到订单事务提交完成。现有 schema 只能稳定采集 `accepted_at → orders.created_at`（订单行创建时间）与首次观察终态上界，因此报告按这两个名称陈述，不写成精确 commit 延迟。HTTP 202 RTT 也不当作成单延迟。
- 并发正确性：固定活动库存和用户集合，包含重复请求/重复消息、最后一份库存竞争、提交后 Ack 前中断、支付与关单竞争、退款与核销竞争、Redis 重建后的旧代际补偿。用 SQL 检查订单唯一、库存范围和流水恒等式，记录每类故障次数及观测错误数。
- 资源与条件：记录硬件、系统、Go/依赖版本、数据库配置、容器限制、Worker 数、Prefetch、连接池、负载脚本和源码哈希。正式性能实验与竞态检测分开，不同时运行另一个项目的压测。
- 复测：先做小规模验证，再进行预先定义的有限负载测试和多轮复测，保留每轮原始结果与波动。没有提升时如实分析；不虚构 QPS、毫秒数、“零超卖生产保证”或真实用户规模。

简历可以最终写“在某种本地负载与故障实验中观察到零重复成单”，前提是附实际数量、条件和证据；不能把模拟支付写成真实渠道接入。性能实测已完成，但只能按 `benchmark-report.md` 中的店铺详情路径、固定负载和单机条件使用，不外推至新增活动缓存。

## 完成标准与工作方式

1. 审计当前代码、配置、进度和简历每条目标，列出已实现、已测试、待实现、待测量与阻塞项；已验证能力先做必要回归，不推倒重做。
2. 先建立能演示的业务闭环，再接入增强能力与恢复验证。按依赖顺序连续推进里程碑，每次通过检查就记录结果并继续；提交计划后即开始可执行工作，不只停在计划或空壳目录。
3. 业务用例、失败验证、运行脚本、迁移和配置随实现交付；缺依赖时只安装本项目所需部分，锁定实际版本。保留已有环境、数据与密钥，不输出密钥。
4. 在优化前保留可复现基线；同代码版本标识、数据版本、硬件、依赖、参数、负载和预算下比较。运行有测量边界，达到既定实验量后停止，不无限压测或循环优化。
5. 每阶段更新进度与风险，记录工作文件、运行命令和原始结果路径；如无 Git，先保存必要快照，评测以源码哈希和版本清单标识，不虚构提交号。不给尚未开始的任务标完成。
6. 同一项目的可变工作目录只由一个执行任务推进。另一个项目可以独立开发，但端口、Compose 项目名、数据卷和输出目录分开；正式性能实验时避免两个项目同时压测。
7. 用已有授权完成本地工作。新增付费调用需要结合已有额度和授权，先估算评测调用量；缺少预算时提出一个具体问题，继续不依赖付费调用的实现和验证。网络/权限/外部服务阻塞不能用模拟成功代替。
8. 每次运行到会话边界时留下准确交接。连续开发不等于自动跨无限回合或绕过使用额度；下一次读最新进度继续，不要求用户重新说明全部项目。

## 模型与推理强度建议

以下是本项目的任务分工建议，不是实测排名，也不是自动模型切换：

| 工作 | 建议设置 |
| --- | --- |
| 主体开发与集成、评测脚本 | GPT-5.6 Sol，High；简单边界明确的工作可用 Medium |
| 明确的小接口、文档或局部修复，需要节省额度 | GPT-5.6 Terra，Medium；复杂问题升至 Sol |
| 关键架构、跨组件恢复、难以定位的故障、最终证据审阅 | GPT-6 Astra，High；仍难收敛时才考虑 Extra High |

如果只想保持一个设置，以 Sol + High 开始。不要默认全程 Max/Ultra；更高推理强度会增加耗时和 token。写代码的 Codex 模型与项目运行时调用的业务模型是两回事，不因换开发模型而更改业务模型。官方信息核对于 2026-09-22；模型与档位以客户端实际可选项为准。

来源：[Codex 模型与推理档位](https://learn.chatgpt.com/docs/models)、[Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)。API 单价不能直接换算成订阅内本项目所需额度；目前没有本项目的模型对照成本或完工时间实测。
